# Menohelp: reconstructed data processing brief

**B0 - Provenance and scope.** Prepared by Sergii Rostovskyi on 17 November 2026 for an educational peer audit of Ben Mayer's **Menohelp / Project Menopause Insights**. This is an auditor-created reconstruction, not a brief supplied or approved by Ben. Source snapshot: `89940e85b3f869b888e247a5b9651020b8d6c865`. The reconstruction uses functional documentation and code, not a teammate's GDPR conclusions. The real brief exchange is outstanding. Reference IDs resolve in the [evidence register](menohelp-evidence-and-sources.md).

**B1 - System and people.** Menohelp combines menstrual-cycle records, optional blood-test PDFs and a symptom form into a personalised explanatory report for adults, primarily women aged 35 to 50+. It provides information for discussion with a health professional, rather than an implemented treatment or eligibility decision. The repository describes a local prototype, with Render and Streamlit Cloud deployment planned. Actual users, operating jurisdiction, legal operator and production usage are unconfirmed. [E1]

**B2 - Input and purpose.** P1 is to collect and analyse a user's cycle dates, lengths, flow and optional age/user ID from CSV or JSON, including Clue exports. Optional PDFs can initially contain names and dates of birth; server-side parsing retains selected analytes, measured values, ranges, draw dates, cycle day and ages derived from birth date. The form adds symptoms, hormone/surgery context and a free-text concern of up to 200 characters. P2 is to retrieve reference material and produce an individual report linking these inputs. No app fine-tuning flow is established. [E2-E4]

**B3 - External processing.** The local Streamlit/FastAPI/LangGraph process calculates statistics and sends statistics and findings to OpenAI for writing and interpretation. Those payloads can include the supplied user ID, dated events, symptom text, selected laboratory values and inferred explanations. Free-text concerns also become OpenAI embedding input for retrieval; Supabase receives query vectors and symptom/lab lookup selectors, while storing the reference corpus. The fact that the model does not receive raw cycle rows does not mean that it receives no individual-level information. [E3-E5]

**B4 - Output and reuse.** P3 is to show the report and chart, optionally download/save outputs, and email the report through Resend to an address entered by the user. Resend receives the address, report content and optional chart attachment. The README labels one public showcase as based on real data, while describing other examples as synthetic or Kaggle derivatives. Whose data that showcase represents and permission for publication are unknown. Publishing a showcase is a separate purpose, P4, from delivering a private report. [E1, E6]

**B5 - Storage and access.** Upload stores use process memory, a one-hour expiry threshold and capacity limits. Expiry runs on store operations, not on a scheduled erasure task. Streamlit also holds session state; CLI exports, recipient mailboxes, provider logs and backups have separate lifetimes. There is an optional shared UI password and lab correction/deletion endpoints; the inspected API has no evident per-user authentication/ownership checks. Deployment access restrictions, comprehensive erasure, retention policies and incident procedures are unconfirmed. [E7-E9]

**B6 - Entities and geography.** Ben is the builder. No separate commissioning client is identified; provisionally the eventual service operator determines purposes, with Ben a processor only if acting for a separate controller. OpenAI, Supabase and Resend are external vendors. Their contracting entities, account settings, regions, subprocessors, accepted DPAs and transfer arrangements were not supplied. P5 covers necessary service/security metadata such as account-linked API requests and network identifiers; exact logging is unknown. Non-EEA access must be investigated, not inferred as a proven US transfer from a vendor name. [E1, E5-E9]

**B7 - Missing governance evidence.** No owner-provided lawful-basis decision, explicit health-data consent, privacy notice, DPIA, vendor-contract pack or rights-request procedure accompanies this reconstructed brief. Their absence from this evidence set does not establish their absence everywhere. No third party has confirmed the assumptions above.
