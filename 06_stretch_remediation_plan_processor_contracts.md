# Stretch · Remediation plan for Finding 1 (processor contracts and transfers)

**Gap:** personal data reaches OpenAI (and Tavily, possibly Pinecone) on every run, with no Art. 28 contract and no documented Chapter V transfer mechanism.

| | |
|---|---|
| **Artifacts that close it** | (1) An executed DPA with OpenAI, or an EU-residency API project with zero data retention. (2) Executed DPAs with Tavily and Pinecone. (3) A one-page transfer record per vendor: entity, region, mechanism (adequacy / DPF / SCCs), transfer impact assessment summary. (4) A processor list added to the records of processing. |
| **Owner** | The **controller** (the consultancy running the tool), with **external counsel** reviewing the transfer impact assessments. Friedrich prepares the technical facts: which data goes where, and the regions configured. |
| **Timeline** | **Week 1:** accept and download the online DPAs, set regions, enable zero retention where offered. **Week 2:** counsel reviews transfer impact assessments, records updated. No real-company runs until the end of week 1. |
| **Evidence for a regulator** | Signed or accepted DPA PDFs with dates; screenshots of region and retention settings in each dashboard; transfer records referencing the SCC modules or DPF certification; a records-of-processing entry listing processors and mechanisms; and a dated log line showing the first real-company run happened after the contracts. |
